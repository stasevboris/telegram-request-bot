# Telegram-бот заявок — руководство по запуску

Это отдельный проект бота на Python и aiogram 3. Он рассчитан на реальную обработку запросов, а не только на демонстрационные кнопки. Бот работает в режиме long polling, поэтому для старта не нужен домен или публичный webhook. Для круглосуточной работы его нужно запустить на постоянно работающем компьютере или VPS.

## Что умеет бот

Клиенту доступны карточки услуг с ориентировочными ценами, примеры проектов, FAQ, этапы взаимодействия, контакты и форма заявки. Форма последовательно собирает выбранную услугу, язык/стек или предмет, желаемый срок, описание и до пяти файлов или изображений; действует ограничение 5 заявок на пользователя за 24 часа. Черновик формы сохраняется в SQLite, переживает перезапуск процесса и автоматически удаляется фоновым заданием после 72 часов без активности.

Каждая принятая заявка сначала записывается в локальную SQLite-базу, затем синхронизируется с Google Sheets (если подключена таблица) и направляется администратору в личный чат либо настроенную группу. Если Google недоступен, локальная запись остаётся целой и повторяется фоновая синхронизация. Если уведомление владельцу не доставлено, бот честно сообщает об этом клиенту.

У администратора есть карточки заявок, статусы, ответы клиенту, передача вложений, статистика, CSV-экспорт, повторная синхронизация и рассылка. Доступ к админ-действиям ограничен числовыми Telegram ID из `ADMIN_IDS` и личным чатом либо группой, явно указанной в `ADMIN_CHAT_ID`. Есть `/mydata` и `/deletedata` для экспорта и запроса удаления данных.

Рассылка работает только для пользователей, которые отдельно включили подписку в разделе «Новости и подписка»; заявка и базовое согласие не добавляют человека в рассылку. Администратор задаёт текст командой `/broadcast`, проверяет предпросмотр и подтверждает отправку кнопкой. Отписка доступна в меню и командой `/unsubscribe`; заблокировавшие бота автоматически исключаются. Онлайн-платежей, CRM и скачивания файлов на сервер нет.

## Файлы проекта

`app.py` запускает polling и фоновую синхронизацию; `config.py` читает настройки; `database.py` отвечает за SQLite; `google_sheets.py` — за таблицу; `content.py` содержит тексты, услуги и кейсы; `keyboards.py` собирает меню; `client_handlers.py` ведёт клиента по сценарию; `admin_handlers.py` управляет заявками; `tests/test_database.py` проверяет слой данных.

## Перед запуском: учётные данные

Никогда не отправляйте токен Telegram или JSON-файл Google Service Account в чат. Не добавляйте их в GitHub. Реальные секреты хранятся только в локальном `.env` и каталоге `credentials/`, которые исключены в `.gitignore`.

### 1. Создать бота и получить токен

В Telegram откройте `@BotFather`, отправьте `/newbot`, задайте название и уникальный username, который заканчивается на `bot`. Скопируйте токен. Дополнительно в BotFather можно задать описание и список команд:

```text
start - открыть меню
help - помощь
privacy - данные и конфиденциальность
myid - показать свой числовой ID
mydata - получить экспорт своих данных
deletedata - запросить удаление данных
subscribe - открыть настройку новостной подписки
unsubscribe - отписаться от новостей
cancel - отменить текущий шаг
admin - панель владельца
leads - список заявок
lead - открыть заявку по номеру
status - изменить статус заявки
reply - ответить клиенту по номеру заявки
stats - сводка по заявкам
export - выгрузить заявки в CSV
sync_pending - повторить синхронизацию Google Sheets
broadcast - создать рассылку с предпросмотром для подписчиков
```

`@BotFather` только регистрирует бота и выдаёт токен. Кнопки, логика диалогов и обработка заявок реализованы этим Python-проектом.

### 2. Подготовить настройки и узнать свой Telegram ID

Скопируйте `.env.example` в `.env`. В PowerShell:

```powershell
cd 'F:\работа\telegram_bot'
Copy-Item .env.example .env
```

Откройте `.env` и замените `BOT_TOKEN` на значение от BotFather. Для первого локального запуска временно оставьте `ADMIN_IDS=0`: это временный режим только для получения своего ID. Запустите бота, откройте с ним личный чат и отправьте `/myid`. Команда показывает ID только вам и не сохраняет его. Остановите бота сочетанием Ctrl+C, впишите показанное число в `ADMIN_IDS`, например `ADMIN_IDS=123456789`, сохраните `.env` и перезапустите.

Не публикуйте ссылку на бота, пока в `ADMIN_IDS` не стоит настоящий ID. Значение `0` не получает уведомления о заявках. Когда настоящий администратор вписан, откройте бота в личке, нажмите `/start`, ознакомьтесь с уведомлением о данных и используйте `/admin`. Это также нужно, чтобы бот мог первым написать вам о заявке. Команды администратора работают только в личном чате или в группе, ID которой явно прописан в `ADMIN_CHAT_ID`; админ-команды из других групп не показывают данные клиентов.

Укажите в `CONTACT_USERNAME` свой публичный username без `@` (например, `borislabs`). Этот адрес показывается клиентам в меню контактов и в уведомлении о данных.

### 3. Установить и запустить локально

Нужен Python 3.11 или новее. В PowerShell:

```powershell
cd 'F:\работа\telegram_bot'
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
python app.py
```

Если PowerShell не разрешает активировать виртуальное окружение, выполните `Set-ExecutionPolicy -Scope Process Bypass`, затем активируйте окружение повторно. Бот остановится при закрытии окна, завершении процесса или выключении компьютера. Это нормально для первичной проверки, но не для постоянной работы.

В другом Telegram-аккаунте нажмите `/start`, примите уведомление, проверьте разделы меню и отправьте тестовую заявку с тестовым файлом. В своём аккаунте проверьте уведомление и команды `/admin`, `/leads`, `/lead 1`, `/stats`, `/export`. Удалите тестовую запись через `/deletedata` от тестового пользователя.

### 4. Подключить Google Sheets

Подключение Google Sheets необязательное для первого теста; SQLite работает независимо. Для интеграции:

1. Создайте отдельную пустую Google-таблицу и скопируйте её ID из адреса: часть между `/d/` и `/edit`.
2. В Google Cloud Console создайте проект, включите Google Sheets API и создайте Service Account с JSON-ключом.
3. Создайте папку `credentials` в проекте и сохраните JSON как `google-service-account.json` внутри неё. Не отправляйте его мне и не добавляйте в репозиторий.
4. Откройте таблицу в браузере и поделитесь ей с email сервисного аккаунта с правами редактора. Без этого API получит отказ в доступе.
5. Заполните `GOOGLE_SHEET_ID`, `GOOGLE_SERVICE_ACCOUNT_FILE=./credentials/google-service-account.json` и при желании `GOOGLE_WORKSHEET=Заявки` в `.env`.
6. На Linux/VPS контейнер работает от UID 10001. Дайте этому пользователю доступ на чтение credentials-файла, сохраняя каталог недоступным для посторонних; например, владелец `10001:10001`, каталог `700`, JSON `600`. На Windows Docker Desktop используйте ACL, ограничивающие доступ вашей учётной записью.
7. Перезапустите приложение и отправьте тестовую заявку. Бот создаст строку заголовков в пустой вкладке. Если вкладка уже заполнена, заголовок должен в точности совпадать с перечнем в разделе «Колонки Google Sheets» ниже.

База SQLite — источник истины, Google Sheets — рабочая копия для просмотра. Статусы синхронизируются, ошибки автоматически повторяются. Если сервисный аккаунт или таблица недоступны, заявка не теряется локально; администратор может исправить настройки и выполнить `/sync_pending`.

### 5. Круглосуточный запуск на VPS через Docker

Для постоянной работы нужен Linux VPS с Docker Engine и Docker Compose Plugin. На компьютере с Docker Desktop этот же вариант подходит для тестов. В папке проекта создайте `.env` по инструкции выше, затем выполните:

```bash
docker compose up --build -d
docker compose logs -f telegram-bot
```

Остановить: `docker compose down`. Перезапустить после изменения `.env`: `docker compose up -d --build`. Данные SQLite находятся в Docker named volume `bot-data` и переживают пересоздание контейнера. Не удаляйте этот volume командой `docker compose down -v`, если хотите сохранить заявки.

В production ограничьте доступ к VPS SSH-ключом и firewall; этому боту не нужно открывать входящий порт, поскольку он использует long polling. При запуске бот удаляет остаточную настройку webhook, сохраняя ожидающие updates. Не включайте одновременно второй экземпляр бота с тем же токеном: Telegram не допускает конкурирующий polling для одного токена. На Linux ограничьте доступ к `.env` командой `chmod 600 .env`.

### 6. Тесты

Из папки проекта:

```powershell
python -m unittest discover -s tests -v
python -m compileall -q .
```

Тесты используют временную SQLite-базу и не отправляют запросы в Telegram или Google.

## Управление заявками

Доступные статусы: `new`, `contacted`, `quoted`, `accepted`, `in_progress`, `delivered`, `closed`, `declined`. Примеры команд:

```text
/admin
/leads
/leads in_progress
/lead 12
/status 12 quoted
/reply 12 Здравствуйте, уточните версию Python и пришлите текст ошибки.
/stats
/export
/sync_pending
```

Также нажмите кнопку заявки в админ-уведомлении, чтобы открыть карточку, ответить клиенту, изменить статус или повторно передать вложения. Кнопка «Ответить клиенту» откроет личный чат с ботом; отправьте там текст ответа. Команда `/cancel` прекращает этот режим.

### Добровольная рассылка

Клиенты не подписываются автоматически. В меню есть отдельный пункт «Новости и подписка»; согласие на рассылку не является условием заявки, его можно отменить в любой момент кнопкой или `/unsubscribe`. `/subscribe` показывает состояние и ссылку на отдельный opt-in. Рассылка разрешена только подписчикам с сохранённым отдельным согласием.

Администратор отправляет `/broadcast Текст сообщения`. Бот показывает предпросмотр, количество получателей и кнопку явного подтверждения. После подтверждения отправляет текст с ограниченной скоростью (около 20 сообщений/сек), считает доставленные и ошибочные сообщения, а пользователей, заблокировавших бота, автоматически отписывает. Черновик рассылки можно отменить до подтверждения. Картинки и отложенная отправка сейчас не поддерживаются.

## Колонки Google Sheets

Вкладка должна иметь такую строку заголовков (порядок важен): `lead_id`, `created_at_utc`, `telegram_id`, `username`, `display_name`, `service_key`, `stack`, `deadline`, `description`, `extra_notes`, `status`, `attachment_count`, `source`, `expected_budget`.

## Данные и конфиденциальность

Бот принимает до 5 файлов и изображений до заданного в `.env` размера (по умолчанию 20 МБ на каждый). Разрешены документы (Word, PDF, Excel), архивы (.zip, .rar, .7z), исходный код и изображения. Файлы не скачиваются на диск сервера. В SQLite сохраняются текст заявки, Telegram ID и метаданные с идентификаторами исходных сообщений; оригиналы остаются в Telegram. Администратору бот копирует вложения в настроенный личный или групповой чат. `/deletedata` удаляет запись пользователя и его заявки из SQLite, пытается удалить строки Google Sheets, исходные сообщения и копии, которые бот отправил администраторам. Ограничения Telegram могут помешать удалить старые сообщения. Файлы, которые администратор уже скачал вне Telegram-чата, бот удалить не может.

Заявки содержат персональные данные. Отдельное согласие на рассылку хранится в `marketing_subscriptions`; `/unsubscribe` отключает его, а `/deletedata` удаляет вместе с профилем и заявками. Ограничьте доступ к SQLite, резервным копиям и Google-таблице. Определите и сообщите клиентам свой срок хранения до публичного запуска; автоматическая очистка удаляет только незавершённые черновики (72 часа) и неподтверждённые черновики рассылок (24 часа), но не отправленные заявки. Сам текст `PRIVACY_NOTICE` в `content.py` — понятное уведомление внутри бота, а не юридическое заключение или универсальная политика конфиденциальности. Проверьте его на соответствие своей реальной практике.

Сделать копию базы в контейнере можно командой (файл будет создан в Docker volume):

```bash
docker compose exec telegram-bot python -c "import sqlite3; c=sqlite3.connect('/app/data/bot.sqlite3'); c.execute(\"VACUUM INTO '/app/data/backup.sqlite3'\"); c.close()"
docker cp boris-telegram-bot:/app/data/backup.sqlite3 ./backup.sqlite3
```

Резервная копия тоже содержит персональные данные: храните её с ограниченным доступом и удаляйте, когда она больше не нужна.

## Что проверить перед публикацией

1. Заменить текстовые цены, контакт и примеры на те, которые Борис подтвердил как актуальные.
2. Удалить любой кейс, который нельзя показывать публично, или на который нет прав. В боте используется нейтральное описание по файлам рабочей папки; цифры о результатах, оценках, оригинальности, экономии или клиентах не заявляются без проверки.
3. Убедиться, что клиент понимает, какие данные хранятся в SQLite и Google Sheets, кто может видеть админ-чат и как запросить удаление.
4. Пройти пробную заявку с отдельного аккаунта и проверить доставку уведомления и строки в таблице.
5. Передавать образовательную помощь как обучение, обсуждение концепций, разбор кода и отладку. Бот не предлагает выполнять оцениваемые задания за студента или обещать оценку/принятие.
